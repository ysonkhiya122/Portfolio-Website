# Editing this site's content

Everything a visitor reads lives in `src/content/`. No copy is hardcoded in a
component, so you never have to open a `.tsx` file to change a sentence. This
guide covers where each field lives, the loop to follow, the rules that will
stop your build, and the traps that have already bitten me.

---

## 1. The one-screen version

```bash
cd Portfolio-Website
npm run dev            # edit, see it live (Vite prints the port)
npm run validate       # content → links → lint → format → tests → build → size
git add -A && git commit -m "content: update <thing>"
```

If `npm run validate` passes, the site is safe to deploy. If it fails, the
error message names the exact field and the rule it broke — you do not have to
guess.

**Never edit these by hand** — they are generated:

| File                                      | Generated by          |
| ----------------------------------------- | --------------------- |
| `public/notes/**/index.html`              | `npm run build:pages` |
| `public/sitemap.xml`, `public/robots.txt` | `npm run build:pages` |
| `public/yash-sonkhiya-cv.pdf`             | `npm run build:cv`    |

`npm run build` runs all three generators first, so a plain
`npm run build && deploy` is always self-consistent.

## 2. Where each field lives

### `src/content/site.ts` — identity, contact, links

Everything used in the header, footer, `<head>`, JSON-LD and the CV header.

| Field                                       | What it controls                                                             | Notes                                                                           |
| ------------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `name`, `role`                              | Nav brand, page title, JSON-LD                                               | `role` appears in the CV footer too                                             |
| `email`                                     | Every `mailto:`, the copy-email palette command, the contact form's fallback | One place only                                                                  |
| `location.city` / `.region` / `.remoteNote` | About "Based" and "Working style" facts                                      |                                                                                 |
| `employer.current`                          | Experience heading context and the Context section                           | ⚠️ Currently `"Accenture"` — see §6                                             |
| `employer.clientDescriptor`                 | The "Generalised" card in the Context section                                | Describes your employer _by domain_, e.g. "a European field-service enterprise" |
| `availability.status`                       | Hero badge, contact CTA, note page footers                                   |                                                                                 |
| `url`                                       | Canonical links, sitemap, `og:url`, robots                                   | ⚠️ Placeholder domain — see §6                                                  |
| `links.github` / `.linkedin`                | Nav, contact, palette                                                        | Absolute URLs                                                                   |

### `src/content/portfolio.ts` — the substance

This is the file you will edit most. It holds the hero copy, the three case
studies, both roles, the skill groups, achievements, education, FAQs and
testimonials.

**Case studies** (`projects[]`) — each becomes a card _and_ a modal:

| Field                    | Rule                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------ |
| `id`                     | kebab-case, `[a-z0-9-]+`. **Becomes the URL** (`#work/<id>`), so changing it breaks shared links |
| `headline`               | 10–90 characters. One sentence of outcome, not a feature                                         |
| `context`, `decisions[]` | The "why", not the "what". `decisions` needs at least one entry, 20+ chars each                  |
| `impact[]`               | Each metric needs `value`, `label` **and `source`** — see §4                                     |
| `stack[]`                | Minimum 2 entries                                                                                |
| `status`                 | `live` \| `internal` \| `archived`. Only `live` projects may have a `live` link                  |
| `timeframe`              | Free text, e.g. `"2025 — Present"`                                                               |

**Experience** (`experience[]`):

| Field          | Rule                                                                            |
| -------------- | ------------------------------------------------------------------------------- |
| `start`, `end` | `YYYY-MM`, or `null` for a current role                                         |
| `promotion`    | Optional `{ title, date }`. Renders as "Promoted to X · N months after joining" |
| `highlights[]` | One achievement per bullet, minimum 20 chars                                    |

> Durations, "N months after joining" and the total years of experience are
> **derived from these dates**. Never type a duration by hand — that is exactly
> how the old site came to claim "18 months to promotion" in one place and
> 32 months in another.

### `src/content/notes.ts` — engineering write-ups

Each entry becomes a card on the home page **and** a real static page at
`/notes/<slug>/`. Adding one:

1. Append to the `notes` array.
2. `body` is a plain array of paragraphs. A string starting with `## ` renders
   as a section heading.
3. Run `npm run build:pages` (or just `npm run build`).
4. Run `npm run validate:links` — it fails if a note has no built page.

### `src/content/sections.ts` — section order and numbering

Section eyebrows ("02 / Selected work") are derived from the `sectionOrder`
array, not typed. To move or rename a section, edit this list only.

### `src/content/assets.ts` — downloadable files

The command palette builds its download commands from this registry, and
`npm run validate:links` asserts every `href` resolves to a real file in
`public/`. Add a download here rather than hardcoding a path in a component.

## 3. The edit loop

```
edit src/content/*.ts
      ↓
npm run validate
      ↓
  ┌──── fail ────┐          ┌──── pass ────┐
  │ read the     │          │ build:pages  │
  │ field + rule │          │ build:cv     │
  │ it names     │          │ → deploy     │
  └──────┬───────┘          └──────────────┘
         └──────────► fix, re-run
```

Useful individual gates while iterating:

| Command                    | Checks                                            | Speed   |
| -------------------------- | ------------------------------------------------- | ------- |
| `npm run validate:content` | Schema + house rules                              | instant |
| `npm run validate:links`   | Every href and anchor resolves                    | instant |
| `npm run lint`             | ESLint, zero warnings tolerated                   | ~5 s    |
| `npm run test`             | 80 tests incl. an axe a11y pass per component     | ~5 s    |
| `npm run size`             | Bundle budgets                                    | instant |
| `npm run visual`           | Screenshots 3 viewports + fails on console errors | ~20 s   |

`npm run validate` is what CI runs. Run it before you push, every time.

## 4. House rules the gate enforces

These are not style preferences — the build fails.

**Every metric needs a source.** `impact[].source` is required and must be 3+
characters. It is the "Measured from production analytics" line under each
number. If you cannot name where a number came from, the honest move is to
drop the metric, not to invent a source. This is the single rule most likely
to stop you, and it is deliberate.

**A `status` must match its links.** A project marked `internal` or `archived`
cannot carry a `kind: 'live'` link. If the app is behind SSO, it is `internal`
and the card shows "In production" with no outward link.

**Ids are unique across projects and experience.** A duplicate fails the build,
because ids become URL fragments.

**Exactly four hero stats.** Two leaves the row ragged; five wraps badly. If
you want three, delete one and adjust `.heroStats` in
`src/components/Hero/Hero.module.scss` at the same time.

**kebab-case everywhere an id appears.** `[a-z0-9-]+` — no capitals, no
spaces, no underscores.

**No dead links.** Every `/`-prefixed href must resolve to a file in `public/`,
a generated note page, or a declared route. Every `#anchor` must be a section
id from `sections.ts`.

## 5. Writing rules that no linter can check

These are the standards the copy is held to. Breaking them will not fail the
build; it will just make the site worse.

**Lead with the outcome, not the stack.** "500–700 coordinators dispatch daily
without a page refresh" beats "Built with React, Redux Toolkit and SignalR".
The stack is a chip at the bottom of the card; it is not the headline.

**Name the trade-off.** Every case study `decision` should have a cost. "We
chose X, which meant giving up Y" is credible. "We used best practices" is
not.

**Attribute team work.** If a number belongs to a team, say so. The Context
section promises this explicitly, so a claim that breaks it makes the whole
page look dishonest.

**No invented awards, no rounded-up numbers.** Everything in `achievements[]`
should be verifiable on request. If it is not, it does not belong.

**Second person, present tense, no exclamation marks.** The voice is a
colleague explaining a decision, not a brochure.

## 6. Things you must change before this goes live

These are placeholders I could not verify. Each is a single edit.

1. **`site.employer.current`** is `"Accenture"`. Confirm it, or change it. The
   content gate prints a reminder note while this value is present.
2. **`site.url`** is `https://yash-sonkhiya.com`. Replace it with your real
   domain, then run `npm run build:pages` so `sitemap.xml` and `robots.txt`
   pick up the new origin. It is also hardcoded in `index.html` (canonical,
   OG, JSON-LD) — update both.
3. **Employment dates** — verify `2023-08 → 2025-07` and `2025-08 → present` in
   `experience[]`. Every duration on the site is derived from them.
4. **Metric sources** — confirm each `impact[].source` is accurate. "Production
   analytics, 90-day average" is a claim, not a placeholder.
5. **Contact form** — it posts to Netlify Forms (`data-netlify="true"`,
   `form-name=contact`, honeypot field `company`), which only works on a Netlify
   deploy. On any other host the POST 404s and the form shows its error state
   with a prefilled `mailto:` fallback — so it degrades honestly rather than
   silently failing, but to actually receive messages you must either deploy on
   Netlify or point the `fetch('/')` call in
   `src/components/Contact/ContactForm.tsx` at your own endpoint and widen
   `connect-src` in `netlify.toml`.

## 7. Traps that have already caused bugs here

**Durations are derived — do not type them.** Covered above, repeated because
it is the defect the original site shipped.

**Changing a project `id` breaks existing shared links.** `#work/<id>` is a
public URL. If you must rename one, consider keeping the old id as an alias:
the parser in `src/lib/caseStudyRoute.ts` returns `null` for unknown ids, so an
old link degrades to the home page rather than a broken dialog — acceptable,
but a 404-free break is still a break.

**Fonts are declared by hand in `src/styles/fonts.css`.** If you change a font
weight or family, edit that file, not the fontsource stylesheet. Importing the
fontsource CSS directly pulls in their Cyrillic, Greek and Vietnamese
`@font-face` blocks plus legacy `.woff` fallbacks: the browser never downloads
them thanks to `unicode-range`, but Vite still copies every file into
`dist/assets`. Declaring the four faces explicitly means the build emits
exactly four font files.

**`noUncheckedIndexedAccess` is on.** `array[0]` is `T | undefined`. This is
why content code uses destructuring defaults and why the tests have a few
non-null assertions. It is deliberate — do not turn it off to silence one
error.

**Prettier owns formatting, including generated files.** `public/notes/` is in
`.prettierignore`. If you hand-edit a generated file, the next build
overwrites you.

**Images.** Anything in `public/` is copied verbatim and served from the root.
Keep the `og-image.png` at 1200×630 or link previews will crop badly.

## 8. Adding a whole new section

1. Add an id and label to `sectionOrder` in `src/content/sections.ts`.
2. Create `src/components/YourThing/YourThing.tsx` and wrap the content in
   `<Section id="..." eyebrow={sectionEyebrow('yourthing')} title="...">` —
   the shell provides the number, focus target, reveal animation and layout.
3. Add the component to `src/App.tsx` in the order you want it to appear.
4. Add a nav link in `src/components/Nav/Nav.tsx` and a palette command in
   `src/components/CommandPalette/CommandPalette.tsx`.
5. Add the component to the axe matrix in
   `src/components/a11y.a11y.test.tsx` so it is covered by the a11y suite.
6. `npm run validate`.

Step 5 is the one people skip. The a11y suite is a matrix of components, not
an automatic crawler — a component that is not listed is not tested.

## 9. Deploying

```bash
npm run validate     # must be green
npm run build        # regenerates notes, CV and sitemap, then bundles
```

Deploy `dist/`. `netlify.toml` already sets the security headers (CSP, HSTS,
`immutable` caching for hashed assets) and the `/api/contact` redirect. On any
other host, port those headers — the CSP in particular is what keeps the site
from being an XSS vector if a dependency is compromised.
